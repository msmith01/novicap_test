This is the working capital risk scoring service: a Python FastAPI app with a Postgres database, packaged in Docker, with Prometheus monitoring. Here is a quick tour of how it is used.
One command starts the stack. Four containers are running: the API, Postgres, Prometheus and Alertmanager.
The health endpoint answers with status ok. It is open, so load balancers can use it.
Scoring requires an API key. Without one, the request is refused with a four hundred and one.
A healthy applicant, with a million in revenue and a hundred thousand requested, is scored low risk, and the response carries the ruleset version and a request ID.
A risky applicant is scored high risk, and the response lists which rules were triggered.
Bad data is never silently scored. An employee count of zero is rejected with a four hundred and twenty two, and the response does not echo the submitted values.
Every decision is stored in Postgres with the ruleset and image version, so any decision can be reproduced weeks later.
The service exposes Prometheus metrics. These are aggregates only, with no identifiers or raw values.
For safe releases, a candidate ruleset can run in shadow mode, or decide for a percentage of applications as a canary. Here, fifty percent canary traffic is split between the live and candidate rules, and the shadow counters record what the candidate would have decided.
Prometheus scrapes the API, loads eight alert rules, and is connected to Alertmanager, so a bad release or drifting inputs raises an alert without needing repayment data.
The same scorer can replay the whole export. Of one hundred ninety six rows, one fifty eight are low risk, thirteen are high risk, and twenty five are rejected for bad data, rather than being imputed.
The API also serves interactive documentation at slash docs.
In summary: a containerised FastAPI and Postgres service with auth, audit history, shadow and canary rollout, monitoring and alerts. The AWS infrastructure is written as Terraform, but has not been applied.
